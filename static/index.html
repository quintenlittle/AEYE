            Voice (local Piper TTS)
            

              
              
              
              
              
              
              
            

            
Fully offline neural speech — nothing leaves this machine. Replies are spoken as they generate, sentence by sentence; use rate to keep pace with the typewriter. Effects: pitch fun (goblin/demon/chipmunk) plus DSP horror chains (dalek, corrupted, radiodemon, possessed, intercom, wraith, hive), and random shuffles the horror effects mid-speech.

            

          

        

        

          

            Dictation (local Whisper STT)
            

              
              
            

            
Click the 🎤 mic by the chat box to dictate. Transcription runs 100% on-device (Whisper) — no audio ever leaves this machine. Enable it via the AI extras (Start Menu ▸ "Install or Repair AI Extras", or install.bat from source). With mic hotkey on, tap Space to start/stop — it's ignored while you're typing in the chat box.

          

        

        

          

            Display
            

              
            

            

              
            

            

              
            

            
The eye is a procedural 78×30 grid redrawn every frame. Hiding it pauses that render loop entirely and expands the chat to fill the window. If the eye stutters while a model runs, a lower cap (e.g. 30–45) is usually steadier than an uneven 60 — the loop can't exceed your display's refresh rate.

          

          

            Web access
            

              
            

            

            
The model reaches the internet only via the web_search and fetch_url tools that this app runs for it, then reads the results back and answers with citations. This is the only feature that leaves the machine — queries/URLs go to a third party (DuckDuckGo by default, no key needed; drop a Tavily/Brave/SerpAPI key in web_keys.txt for better results). Off = nothing is sent, fully offline. Call = the model must explicitly ask; the app never auto-searches. Auto = the app may also search on its own for clearly time-sensitive requests. A dedicated tool (weather, files, RSS) is always preferred over generic web search. Fetches to localhost/private hosts are blocked.

          

          

            Price tickers
            

              
            

            
Scrolling price tickers along the top of the window — commodities on the left, crypto on the right. They fetch prices (Yahoo Finance, with CoinGecko as a crypto fallback; refreshed each minute) only while web access above is on — so they inherit the same opt-in and stay silent while the app is offline; when web is off or unreachable each strip reads ticker offline.             Board tickers
            
Extra scrolling strips under the price tickers — one lane per 4chan board, showing thread titles only (click a title to open the thread). 4chan can't be read directly, so the strips fetch through a feed relay: the bundled local relay (runs on your machine, fully private) or your own custom relay. Everything is off by default — the strips run only when web access (above) is on, the master switch below is on, and a relay mode other than “off” is picked.

            LLM Tool Access (agentic)
            
            
Off by default — AEYE stays purely interactive. On: the model can call built-in file tools and any plugin marked "type":"tool", within the limits below.

            

              
              
            

            

              
              
              
            

            
            
            

              Performance-test profile is ON (tickers & eye off at startup, Qwythos-Mythos-5 default if installed). Your saved model/ticker/eye choices always win.
              
            

            

              Read Only = read/list files only · Read + Write = also create/overwrite files ·
              Autonomous = also run command tools. All file access is confined to the workspace folder —
              paths outside it are rejected. A tool plugin manifest adds:
              "type":"tool", "description", "access":"read|write|exec",
              "args":[{"name","type","description","required"}]; use {argname} in its command.
            

          

          

            Tool Registry — model-callable tools
            
Everything the model can call, from one authoritative registry. Source may be built-in (enforced in the backend, not user-editable), plugin (from an installed "type":"tool" plugin — fully hackable via edit/code), or web (network tools gated by the web-search policy). Rows dim when the active Permission mode above blocks them. New tool plugins appear here automatically — nothing is hardcoded.

            Installed Plugins
            
Installed extension packages. A plugin may expose a model-callable tool ("type":"tool" — also listed in the Tool Registry above) or provide regular command/trigger behavior you invoke by typing its trigger.

            

              
              
              
            

            

              
New plugin — write the code, hit create

              

                
                
                
                
                
                
              

              
              

                
                
                
              

            

            

              
              
            

            

              

                
plugintypetriggerrunssetup

                
              

            

            

            

              
editing  /
                

              
              

                
                
                
              

            

            

              + new: write a plugin from scratch right here — name it, pick a language (Node/Python), write the
              code, hit create. It lands in plugins/ and opens in the editor.

              Clone from GitHub: paste a repo URL above and hit clone — AEYE clones it into
              plugins/ and (if the repo has no manifest) scaffolds one, opening it here to edit. Or drop a
              repo into the plugins/ folder by hand and rescan. Use the editor's file dropdown to edit
              either the manifest or the code. Then set the tool up:
              install deps for its requirements.txt, and edit the manifest's command/trigger.

              In chat, start a message with a plugin's trigger and the rest is passed to the tool (e.g.
              echo: hello). Plugins run only when you type the trigger, never from a model's reply.

              Manifest: { "name", "trigger", "command": ["python","tool.py","{query}"], "mode", "cwd", "timeout" }
              — mode is stream (default), terminal (own console) or interactive (in-chat session).
